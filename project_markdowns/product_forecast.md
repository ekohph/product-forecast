# Product Forecast — 설계 및 작업 규약

## 목적과 현재 범위

제품 예측 업무를 위한 웹앱을 구성한다. 현재 화면은 제품/Phase/Version 선택과 조회·편집·비교 탭,
Build별 월별 로드맵 편집과 로컬 DuckDB 저장·조회를 제공한다. 기존 계획·버전·Phase API는 유지하지만 계획 생성 화면은 표시하지 않는다.
예측 데이터나 결과를 임의로 만들지 않는다.

## 확정 사항

- ROOT는 현재 `projects` 디렉토리다.
- 프런트엔드: Node.js 22 이상, Next.js App Router, React, TypeScript, npm.
- 백엔드: Python 3.12.x, FastAPI, Pydantic, Uvicorn.
- 화면 경로: `/product-forecast`.
- API 경로: `/product-forecast/api/v1`.
- 기존 서비스 메뉴에서 같은 도메인의 화면 경로로 이동한다.
- 프런트엔드와 백엔드는 별도 프로세스로 실행한다.

## 디렉토리 책임

- 다른 PC의 mother webapp 통합 작업은 `project_markdowns/MOTHER_WEBAPP_HANDOFF.md`를 따른다. 공개 저장소 생성/push 절차는 `project_markdowns/GITHUB_PUBLISH.md`에 있다. 프로젝트 ROOT는 독립 Git 저장소이며 실데이터·환경파일·로컬 실행 도구를 포함하지 않는다.

│   │   ├── features/        # 기능별 UI와 로직; health, plans
│   │   ├── lib/             # API 클라이언트, 경로, 공통 유틸

│   ├── public/

│   ├── app/

계획 데이터는 SQLite에 저장하며 services/plans.py에서 저장과 업무 규칙을 처리한다.
기본 파일은 backend/data/forecast.sqlite3이며 Git에서 제외한다. 최초 요청 시 테이블을 생성한다.
로드맵은 services/roadmaps.py를 통해 별도 DuckDB 파일 backend/data/roadmaps.duckdb에 저장한다.
기존 SQLite 파일과 API는 그대로 유지하며 두 파일은 서로 변환하지 않는다. DuckDB 파일과 WAL은 backend/data 아래에 있어 Git에서 제외한다.
공통 UI가 생기기 전에는 빈 components 디렉토리를 유지한다.

## 개발 규약

- 작업 시작 시 이 문서와 ROOT/AGENTS.md를 읽는다.
- 필요한 경우 subagents를 사용한다. 하위 에이전트는 GPT-6 Luna (`gpt-6-luna`), effort `high`를 사용한다. 전체 계획 및 검증은 현재 작업 중인 모델이 수행한다.
- 페이지는 화면 구성에 집중하고 기능별 코드는 features에 둔다.
- 브라우저 API 호출은 lib의 공통 클라이언트로 모은다. 내부 백엔드 주소를 브라우저에 노출하지 않는다.
- API 라우터는 HTTP 처리를 담당하며 업무 로직은 services로 분리한다.
- 요청·응답 모델은 schemas에 정의한다. 공개 API 변경 시 TypeScript 타입과 호출 코드도 함께 갱신한다.
- 비밀값 및 로컬 환경 파일은 커밋하지 않는다. `.env.example`에는 비밀값 없는 예시만 둔다.
- npm 잠금 파일을 커밋하고 재설치는 `npm ci`를 사용한다.
- 기존 파일과 상위 저장소의 다른 프로젝트 변경 사항은 보존한다.
- 구조, API, 환경변수 또는 실행 방법 변경 시 같은 작업에서 이 문서와 필요한 README를 수정한다.
- 변경 이력에는 날짜, 변경 내용, 이유를 적는다. 미정 사항을 구현된 기능처럼 기술하지 않는다.

## 경로 및 연결 계약

- 2026-11-27: 제품별 탭(조회·편집·비교)과 공통 탭(제품 모아보기·Features)를 구분한다. 제품·Phase·Version과 독립적인 기능 목록에서 기능명, 설명, 적용 제품(0개 이상)을 편집한다. `GET/PUT /product-forecast/api/v1/roadmaps/features`는 `{revision, features: [{id, name, description, products}]}`를 사용한다. 서버는 DuckDB의 `feature_catalog`에 저장하고 오래된 revision의 저장은 409로 거절한다.

- 로드맵 공유 URL은 `/product-forecast?product=4175&phase=Plan&version=0.0` 형식이다. 공통 셀렉터 오른쪽의 `링크 복사`로 현재 제품·Phase·Version의 URL을 복사하며 열면 조회 탭에서 모든 Build의 최신 저장본을 표시한다. 미저장 draft와 비교 선택은 공유하지 않는다. URL 값은 URLSearchParams로 인코딩하고 로드 시 제품·Phase 및 해당 Phase의 Version 존재 여부를 검증한다. 잘못된 링크는 다른 로드맵으로 대체하지 않고 오류를 표시한다.
- roadmap-link.ts가 URL 변환을, roadmap-share.tsx가 클립보드 복사와 수동 복사 팝업을 담당한다. API·DB 변경은 없다. 공유 주소는 현재 접속 호스트를 사용하므로 다른 사용자가 접근 가능한 서버 주소로 접속하여 복사해야 한다. localhost/127.0.0.1 주소는 다른 PC에서 사용할 수 없다.

Next.js basePath와 브라우저 API 기본 경로는 frontend/src/lib/paths.ts에 둔다.
FastAPI prefix는 backend/app/core/config.py에 둔다. 경로 변경 시 양쪽과 통합 테스트를 함께 수정한다.
Next.js basePath는 빌드 시 결정되므로 변경 후 재빌드한다.

개발 환경에서는 Next.js rewrite가 API 요청을 FastAPI로 전달하며 전체 경로를 보존한다.
운영 환경에서는 프록시가 `/product-forecast/api/v1` 및 그 하위 경로를 FastAPI로 먼저 전달하고,
나머지 `/product-forecast` 하위 경로는 Next.js로 전달한다. 프록시에서 prefix를 제거하지 않는다.
정적 자산 경로 `/product-forecast/_next/`도 Next.js로 전달한다.
동일 출처 호출을 기본으로 하므로 CORS 허용 범위를 추가하지 않는다.

| 메서드 | 경로 | 응답/용도 |
| --- | --- | --- |
| GET | `/product-forecast/api/v1/health` | `{"status":"ok","service":"product-forecast"}` |
| GET / POST | `/product-forecast/api/v1/plans` | 전체 계획 조회 / 생성 |
| POST | `/product-forecast/api/v1/plans/{plan_id}/versions` | 버전 추가 |
| POST | `/product-forecast/api/v1/plans/{plan_id}/phases` | Phase 추가 |
| PATCH | `/product-forecast/api/v1/plans/{plan_id}/phases/{phase_id}` | Phase 이름 편집 |

| GET | `/product-forecast/api/v1/roadmaps/catalog` | 선택 목록. `phase` 쿼리 지정 시 version은 해당 Phase에 한정 |
| GET | `/product-forecast/api/v1/roadmaps/versions` | `phase`의 `{version, updated_at, roadmap_count, has_content, content}[]` 목록 |

| GET | `/product-forecast/api/v1/openapi.json` | OpenAPI 스키마 |

브라우저 연결 확인은 5초 제한, 오류 안내 및 버튼으로 재시도를 제공한다.

## 검증 기준

### Python 3.12 호환성 점검 (2026-11-22)

- Windows x64 CPython 3.12.16의 별도 `.tools/venv312` 환경에서 `backend[dev]` 설치, 의존성 일관성 검사, Python 파일 19개 컴파일, 백엔드 pytest 11개가 통과했다. Uvicorn을 임시 포트에서 구동한 실제 HTTP health 응답도 확인했다.
- 확인한 주요 버전: FastAPI 0.165.0, Pydantic 2.14.4, pydantic-settings 2.16.3, DuckDB 2.0.1, Uvicorn 0.54.0, pytest 9.2.0. Python 3.12 호환성 수정을 요구하는 코드는 발견하지 못했다.
- 재검증: ROOT에서 `.\.tools\venv312\Scripts\python.exe -m pytest backend/tests -p no:cacheprovider`. 이 환경은 최초 호환성 점검용이다. 이후 정식 전환 작업에서 `backend/.venv`도 Python 3.12.16으로 재생성했다. Python 버전을 바꾸려면 해당 버전으로 가상환경을 새로 만들어 의존성을 설치해야 한다.
- 테스트 시 Starlette의 httpx 사용 중단 예정 경고 1건이 있으나 Python 3.12 오류는 아니다. 의존성 대부분은 범위 지정이므로 향후 설치 버전은 달라질 수 있으며 본 결과는 위 환경 기준이다. 프런트엔드 및 PNG/PPTX 내보내기는 Node.js/브라우저 코드로 Python 버전에 의존하지 않는다.

### 일반 검증

- Next.js 프로덕션 빌드와 TypeScript 검사가 통과한다.
- pytest로 상태 응답, OpenAPI 경로, 문서 URL 및 prefix 없는 경로의 404를 확인한다.
- 양쪽 서버 실행 후 `npm run test:smoke`로 화면, 경로가 붙은 JavaScript 자산, 동일 출처 API 응답을 확인한다.
- UI 변경 시 연결 성공, 백엔드 중단 시 오류, 재시도 및 모바일 화면을 확인한다.

### 필요 기능의 구현 기준

- 2026-11-22: 조회 타임라인은 왼쪽에 미선택 체크박스와 Build 이름을 배치한다. Build별 카드 헤더·테두리·간격을 제거하고 같은 배경으로 연결한다. 날짜·이름 충돌 시에만 행 높이를 늘리고, 빈 일정 안내는 타임라인 안에 작게 표시한다. 스크롤 최소화와 정보 밀도를 우선하는 UI 지침은 ROOT/AGENTS.md를 따른다.

- 2026-11-21: 각 Build 표 바로 아래 `roadmap-timeline.tsx`에서 표시된 월 범위의 일정을 가로 타임라인으로 요약한다. 일정 시작·종료일에는 날짜 없는 세로선을 표시하고 표시된 기간 중앙에 항목명을 배치한다. 날짜 라벨은 마일스톤에만 표시하고 마일스톤은 원과 이름으로 표시한다. 한국 시간 오늘 이전 마일스톤은 검은 테두리·파란 채움, 오늘 및 이후는 진한 회색 테두리·연한 회색 채움을 사용한다. 현재 날짜는 포커스 복귀 및 1분 간격으로 갱신한다. 같은 날짜는 눈금을 합치며 숨긴 월은 제외한다. 첫 마일스톤과 연도 변경 후 첫 마일스톤만 `'26 01/01` 형식으로, 이후에는 `01/31` 형식으로 표시한다. 날짜는 선 위, 마일스톤 이름은 선 아래에 배치하고 가까운 라벨은 높이를 나눈다. 내용은 툴팁으로 제공한다. 화면 너비와 편집 중 날짜 변경에 반응하며 저장/API 계약은 변경하지 않는다.

- Edit 모드에서 항목 박스를 좌클릭하면 선택 테두리를 표시한다. 선택한 박스를 다시 누른 채 좌우로 드래그하면 잡은 지점의 날짜 차이만큼 시작일·종료일을 함께 이동한다. 행 순서와 기간 길이는 유지하며 표시 범위를 넘는 이동은 제한한다. 마일스톤은 Target Date를 이동한다. 포인터 취소/Esc는 드래그를 되돌리고 좌우 방향키는 선택 항목을 하루씩 이동한다. Save Changes로 저장하며 Cancel은 이동을 포함한 임시 변경을 폐기한다.
- 각 Build 표의 Edit 모드에서만 Sort by를 제공한다. 조회 모드에서는 정렬 선택 UI를 숨기고 저장된 정렬을 적용한다. 옵션 순서는 Start Date (Ascending), End Date (Ascending), Milestone Date (Ascending), Start Date (Descending), End Date (Descending), Milestone Date (Descending)이다. 기본값은 Start Date (Ascending)이다. Start/End는 전체 항목의 날짜를 비교하며 Milestone Date는 마일스톤을 날짜순 정렬하고 일반 기간 항목을 뒤에 기존 순서로 둔다. 동일 날짜의 순서는 유지한다. Edit 모드의 정렬 선택은 즉시 표시 순서에 반영하며 Save Changes로 표의 선택 조합별 DuckDB 데이터에 저장한다. 정렬만 바꿔도 저장 버튼이 활성화되고 Cancel은 저장된 정렬로 복원한다. 재조회 시 저장된 정렬을 사용하며 저장값이 없는 기존 표는 Start Date (Ascending)을 적용한다. 드래그 중에는 행 순서를 유지하고 정렬을 다시 선택하거나 저장 후 조회할 때 날짜순을 적용한다.

- 현재 페이지는 `roadmap-workspace.tsx`에서 조회/편집/비교 탭을 구성한다. 다시 불러오기, 신규 제품 계획 및 기존 계획 상세 화면은 표시하지 않는다. 서비스 연결 카드도 제거하고 기존 API는 유지한다.
- 조회는 상단에서 선택한 제품·Phase·Version에 대해 모든 Build의 타임라인을 목록 순서대로 표시하며 월별 표와 편집 버튼은 표시하지 않는다. 편집 탭은 selector의 제품·Phase·Version을 기준으로 모든 Build의 독립된 표를 목록 순서대로 표시하며 Build 선택으로 필터링하지 않는다. 각 표는 저장소 조회 후 즉시 편집 가능하고 기본 타임라인/Expand 표시를 유지한다. 저장·취소·정렬·펼침 상태는 Build별로 독립적이다. 추가·이름 변경·순서 저장 결과를 즉시 반영한다. 현재 Build 목록은 제품 간 공통이며 제품별 저장 모델은 후속 작업이다.
- 월 열은 한국 시간(Asia/Seoul)의 조회 월부터 다음 분기 마지막 월까지 포함한다. 예: 2026-11 조회는 2026-11~2027-03. 분기는 달력 기준이며 분기 헤더는 '26 Q4와 같은 형식이다. `roadmap-months.ts`에서 계산하고 화면 진입/포커스 복귀/1분 간격으로 갱신한다.
- 초기 표는 빈 상태로 표시하며 우클릭 메뉴로 항목을 추가할 수 있다. 일정은 DuckDB에서 불러오며 비교 탭은 기준·대상 선택 후 저장된 일정을 공통 날짜 축에 중첩하고 항목별 추가·삭제·변경을 표시한다.
- 편집 탭에 진입하면 같은 제품·Phase·Version의 모든 Build 표가 바로 편집 모드로 열린다. 우클릭 메뉴, 항목 편집·삭제와 기간 조정은 편집 모드에서만 가능하다. 모든 변경은 임시 상태에 반영하며 Save Changes는 편집 시작 시점과 실제 변경이 있을 때 활성화한다(항목명 입력 중에는 Enter/Tab으로 이름 편집을 먼저 완료). Save Changes는 DuckDB 저장 성공 응답 후 저장본을 새 기준으로 삼고 편집 모드를 유지한다. 실패하면 오류를 표시하고 임시 편집 내용을 유지한다. 저장 중에는 추가 편집과 중복 저장을 막는다. Cancel은 월 열·항목·이름·기간의 미저장 변경을 버리고 서버의 최신 저장 상태를 다시 불러온다. 탭 또는 선택 조합을 바꿔 표가 해제되면 미저장 변경도 폐기된다. 조회 탭으로 돌아오면 모든 Build의 저장본을 다시 읽어 최신 타임라인을 표시한다. 로드맵 저장은 서버 로컬 DuckDB에 영구 반영된다.
- `build-table.tsx`에서 표 상단/빈 영역의 우클릭 메뉴를 제공한다. 항목 추가 팝업은 1행에 이름, 2행에 Start Date / End Date를 제공하며 날짜 입력 클릭 시 브라우저 기본 달력을 연다. 기본값은 대상 월 1일과 실제 말일(31일이 없는 달은 30/28/29일)이다. 종료일이 시작일보다 빠르면 추가할 수 없다. 지정한 기간에 필요한 월 열이 없으면 추가한다. 우클릭한 가로 위치의 월 열을 기본 대상으로 한다. 월 셀뿐 아니라 분기·제품명 행과 항목 옆 빈 공간에서도 실제 월 헤더 위치를 기준으로 판별하며 가로 스크롤을 반영한다. 월 열 범위 밖에서는 마지막 표시 월을 기본 대상으로 한다. 메뉴의 대상 월 선택으로 삭제할 열을 바꿀 수 있다.

- Edit 모드에서 항목·마일스톤 위 우클릭은 항목 편집/항목 삭제 메뉴를 연다. 항목 편집은 추가와 동일한 팝업에 현재 이름·날짜(마일스톤은 내용·Target Date 포함)를 채운다. 적용은 기존 ID와 행을 유지하며 임시 편집 상태를 갱신하고, 닫기/Esc는 팝업 입력을 버린다. 항목·마일스톤을 더블클릭하거나 박스에 포커스 후 F2를 누르면 이름만 인라인 편집한다. 이름은 박스 위치에서 입력하고 Enter 또는 Tab으로 저장하며, 포커스를 옮겨도 유효한 이름은 저장한다. Esc는 취소, 공백 이름은 저장하지 않는다. 항목 삭제는 해당 항목을 즉시 페이지 상태에서 제거한다.
- `roadmap-items.ts`는 월별 일수, 종료일 포함 좌표 계산과 크기 조정 경계를 담당한다. 검증은 frontend에서 `node --experimental-strip-types --test tests/roadmap-items.test.mjs tests/roadmap-months.test.mjs`로 실행한다.

- 로드맵은 제품명·Build명·Phase명·Version명 조합별로 DuckDB에 저장한다. 선택 전환 후 복귀/새로고침/다른 사용자 접속 시 해당 조합을 조회한다. 데이터가 없는 조합만 기본 빈 표를 표시하고 저장된 빈 월 목록도 그대로 복원한다. 이름을 변경해 저장하면 별도 조합이 되며 기존 저장본은 유지한다. 저장한 표의 월 구성은 주기적 날짜 갱신으로 덮어쓰지 않는다.
- 월 범위 검증: frontend에서 `node --experimental-strip-types --test tests/roadmap-months.test.mjs`로 연도·분기·한국 시간 월 경계를 확인한다.

- 상단 선택 바는 `features/plans/selection-bar.tsx`에서 관리한다. 접속 시 기본 옵션에 저장된 로드맵의 제품/Build/Phase/Version 이름을 합쳐 복원한다. 선택된 조합의 표는 `saved-build-table.tsx`에서 조회하며 응답 대기/실패 시 편집 가능한 빈 표로 대체하지 않는다. 미저장 옵션 추가·정렬·삭제는 현재 접속에만 적용되며, 로드맵 저장에 사용된 이름만 다음 접속에도 목록에 나타난다. 옵션 Del은 저장된 로드맵을 삭제하지 않으므로 재접속 시 이름이 다시 표시될 수 있다. 좁은 화면에서는 가로 스크롤한다.
- 각 추가 항목은 해당 제품/Build/Phase/Version 목록 관리 모달을 연다. 표의 행마다 이름, 위·아래 이동, Edit을 제공한다. 처음/마지막 행의 범위 밖 이동은 비활성화한다.
- 제품·Build·Phase 목록은 Edit 오른쪽에 Del을 제공한다(Version 제외). 클릭 시 해당 행을 현재 페이지 상태에서 즉시 삭제하고, 선택된 항목을 삭제하면 남은 첫 항목을 선택한다. 마지막 항목도 삭제할 수 있으며 빈 목록에서 추가는 계속 가능하다. 이름 편집 중에는 다른 행의 편집·삭제를 비활성화한다. 삭제는 다른 미저장 순서/추가 입력을 저장하지 않는다. DB 데이터는 삭제하지 않는다.
- Edit 시 이름 입력과 Cancel / Save as를 표시한다. Cancel은 해당 이름 편집을 취소하며, Save as는 이름과 현재 순서를 저장한다. 새 항목 추가 시에도 현재 순서를 함께 저장한다. 순서만 변경한 경우 순서 저장 버튼을 사용한다. 이 목록 편집의 저장은 현재 페이지 옵션 상태에 반영한다. 로드맵 표의 Save Changes와 구분한다.
- 오른쪽 위 닫기 또는 Esc로 팝업을 닫는다. 저장 전 이름·순서·추가 입력이 있으면 변경을 버릴지 확인하며, 취소하면 편집을 유지한다. 새로고침/탭 종료 시 미저장 변경은 브라우저 기본 경고를 요청한다.

- 신규 계획은 제품명과 계획명으로 생성하며 기본 Phase는 `계획`, `내부 협의 완료`, `고객 협의 완료`다.
- Phase는 계획별로 관리한다. 추가와 이름 편집을 지원하며 이름 변경 시 선택 버전은 보존한다.
- 버전은 계획별 이름과 자유 형식 계획 내용의 불변 스냅샷이다. 수정안은 새 버전으로 추가한다.
- 각 Phase는 해당 계획의 버전 하나를 독립적으로 선택하거나 미선택으로 해제할 수 있다. 같은 버전을 여러 Phase가 선택해도 된다.
- 버전명과 Phase명은 같은 계획 안에서 중복을 허용하지 않는다. 앞뒤 공백은 제거하며 이름은 1~120자, 내용은 최대 20,000자다.
- 생성 요청은 계획 `{product_name, name}`, 버전 `{name, content}`, Phase `{name}`이며 이름 편집은 `{name}`, 선택은 `{version_id: UUID 또는 null}`이다.
- 계획 응답은 `{id, product_name, name, versions: [{id, name, content}], phases: [{id, name, version_id}]}`이며 변경 API는 갱신된 전체 계획을 반환한다.
- 없는 계획/Phase는 404, 중복 이름은 409, 입력 오류와 다른 계획의 버전 선택은 422다.
- 기존 계획 API의 저장은 SQLite 트랜잭션으로 처리한다. 기존 Phase의 동시 선택 변경은 마지막 저장이 적용된다. 인증·사용자별 접근 제어와 기존 계획 삭제 API는 아직 범위에 포함하지 않는다. 로드맵 화면은 아래 DuckDB 계약을 따른다.
- pytest는 Phase별 독립 선택, 선택 해제, 이름 변경 시 선택 보존, 재연결 후 저장 유지, 잘못된 참조 및 입력 검증을 확인한다.


### DuckDB 저장 계약 및 운영

- data.sort는 Sort by의 6개 옵션 문자열 중 하나다. 요청 또는 기존 저장 payload에 없으면 Start Date (Ascending)을 적용하고 조회 응답에는 기본값을 포함한다. 잘못된 옵션은 422로 거절한다.

- 마일스톤은 기존 items 배열에 `{id, name, kind: "milestone", content, startDate, endDate}`로 저장한다. startDate와 endDate는 동일한 Target Date이며 서로 다르면 422다. content는 최대 20,000자, 이름은 1~120자다. 기존 기간 항목의 JSON 형식은 그대로 허용한다. 저장된 기존 DuckDB payload는 별도 이관 없이 읽을 수 있다.
- 편집 모드 우클릭 메뉴에서 항목 추가 다음에 마일스톤 추가를 제공한다. 팝업은 마일스톤 명, 마일스톤 내용(선택), Target Date 달력을 제공한다. 기본 Target Date는 대상 월 1일이다. 추가하면 목표일 위치에 ◆와 이름, 아래에 날짜를 표시하고 마우스를 올리면 내용을 확인할 수 있다. 표시 범위 밖 날짜를 선택하면 해당 월을 추가한다. Save Changes / Cancel과 기존 항목명 편집·삭제 흐름을 공유하며 기간 크기 조정은 제공하지 않는다.

- 파일은 브라우저 PC가 아닌 FastAPI를 실행하는 서버 PC에 저장된다. 같은 서버에 접속한 사용자는 같은 저장본을 조회한다. 기존 인증/권한 미구현 상태는 유지한다.
- DuckDB Python 의존성은 검증된 `duckdb==2.0.1`로 고정한다. 기존 환경 갱신은 README의 uv 설치 명령을 따른다.
- 서버는 단일 Uvicorn worker로 실행한다(기본값). 프로세스 내 잠금으로 연결 및 쓰기 트랜잭션을 직렬화하며 각 작업 후 파일 연결을 닫는다. 동일 파일을 여러 백엔드 프로세스/PC에서 동시에 쓰지 않는다. [DuckDB 동시성 문서](https://www.duckdb.org/docs/current/connect/concurrency)를 따른다.
- GET/PUT `/roadmaps`는 쿼리 `product`, `build`, `phase`, `version`을 모두 받는다. 각 이름은 공백 제거 후 1~120자다.
- PUT 본문은 `{revision, data: {months, items, sort}}`다. months는 기존 `{key, label, year, quarter}` 배열(최대 1,200개), items는 `{id, name, startDate, endDate}` 배열(최대 5,000개)이다. 날짜 역전, 중복 ID/월, 정렬되지 않은 월, 잘못된 월 정보는 422로 거절한다. 숨겨진 월의 항목도 보존한다.
- 응답은 `{revision, data, updated_at}`이며 아직 저장되지 않은 조합은 200과 `{revision:0, data:null, updated_at:null}`을 반환한다. 저장 시 revision을 1 증가시키며 updated_at은 UTC ISO 날짜다.
- 동일 조합의 revision이 달라졌으면 409로 저장을 거절하여 다른 사용자의 수정을 보호한다. 화면은 편집 내용을 유지한다. Cancel로 최신본을 읽고 다시 편집한다. 저장소 오류는 503이며 성공 안내를 표시하지 않는다.
- GET `/roadmaps/catalog`는 `{product:[], build:[], phase:[], version:[]}`를 반환한다. `phase`를 지정하면 버전 목록만 해당 Phase에 한정한다. 기존 제품/Build/Phase 이름 변경·삭제는 저장본에 전파하지 않지만 Version 삭제는 아래 계약에 따라 저장본도 삭제한다.
- 이전 버전의 브라우저 메모리에만 있던 미저장 편집은 자동 이관할 수 없다. 새 화면에서 Save Changes로 저장한 로드맵부터 접속 간 공유된다.
- 검증: 별도 API 클라이언트/새 Python 프로세스에서 복원, 조합별 분리, 월 삭제와 빈 표 저장, 동시 수정 충돌, 잘못된 입력 및 저장소 장애를 pytest로 확인한다.


### 비교 대상 선택 (2026-11-22)

### 타임라인 다운로드 (2026-11-22)
- 기간이 겹치는 화살표는 첫 번째를 공통 타임라인에 놓고 이후 화살표는 아래 4px, 위 4px, 아래 8px, 위 8px 순으로 하단·상단을 번갈아 배치한다. 날짜는 최상단 화살표 위, 항목명은 최하단 화살표 아래에 배치한다. 겹치지 않는 기간은 같은 높이를 재사용한다. 항목명과 마일스톤명은 화살표 묶음 아래에서 텍스트 겹침을 피하며 14px 줄 간격으로 조밀하게 배치한다. 날짜와 마일스톤은 공통 시간축에 유지하며 PNG/PPTX에도 동일 배치를 반영한다.
- 기간 항목 안쪽의 타임라인 선·화살촉·항목명은 검정 RGB(0, 0, 0)으로 표시하며 PNG/PPTX에도 동일하게 반영한다. 항목 밖의 시간축과 날짜 표기는 기존 색상을 유지한다.
- 기간 항목의 시작·종료 세로선을 유지하고, 기간 안쪽에서 세로선을 향하도록 시작은 왼쪽 방향(‹), 종료는 오른쪽 방향(›) 화살촉으로 표시한다. 화살촉 끝은 실제 날짜 위치에 고정하며 같은 날짜에 시작·종료가 함께 있으면 두 방향을 표시한다. 마일스톤 원과 날짜 이동 점선은 유지한다. 화살촉은 SVG 선으로 구성해 PNG 및 편집 가능한 PPTX에도 동일하게 포함한다.
- 조회·편집의 공통 타임라인에서 기간 항목의 시작일/종료일도 MM/DD로 표시한다. 같은 날짜는 하나로 합치고 마일스톤의 연도 전환 표기는 유지한다. timeline-labels.ts에서 날짜 텍스트를 좌우 이동해 겹침과 영역 이탈을 방지하며 한 줄 폭이 부족할 때만 추가 줄을 사용한다. 실제 세로선 위치는 고정하고 이동된 날짜에는 점선(dashed) 연결선을 표시한다. 동일 SVG를 캡처하므로 PNG와 편집 가능한 PPTX에도 반영된다.
- 조회 헤더의 Phase·Version은 제품명 옆에 표시하고 Download는 오른쪽 정렬한다. timeline-view.tsx에서 Build별 체크 상태를 관리하며 모두 미선택으로 시작한다. 제품·Phase·Version 또는 탭을 바꾸면 선택을 초기화한다. 유효한 선택이 1개 이상일 때만 Download를 활성화한다.
- timeline-export.ts는 선택된 Build의 화면 SVG에 계산된 스타일을 복사하고 브라우저 Canvas로 PNG를 합성한다. Build 순서·색상·날짜·항목명과 제품/Phase/Version 헤더를 포함하며 체크박스·버튼은 제외한다. 월이 없거나 로딩/오류 상태인 표는 잘못된 빈 파일을 만들지 않고 오류를 표시한다. 팝업에서 이미지 미리보기와 PNG 다운로드/PPTX 다운로드 버튼을 제공한다. 형식 선택 없이 해당 버튼으로 바로 다운로드하며 미리보기 준비 전과 파일 생성 중에는 두 버튼 모두 비활성화한다.
- PNG는 미리보기 이미지 그대로 저장한다. PPTX는 선택한 Build의 화면 SVG에서 원·선·텍스트와 계산된 위치/색상을 함께 캡처한 뒤 timeline-pptx.ts에서 편집 가능한 PowerPoint 개체로 변환한다. 16:9 슬라이드 한 장에 비율을 유지하고 전체 타임라인 그룹 안에 Build별 그룹을 중첩한다. pptxgenjs 4.0.0과 jszip 3.10.1을 다운로드 시 지연 로딩하며, JSZip으로 표준 DrawingML 그룹을 구성한다. image-size 간접 의존성은 2.1.0으로 override한다. 내보내기 데이터는 외부 서비스나 서버로 전송하지 않는다. 기존 환경은 frontend에서 npm ci로 의존성을 반영한다. 검증: node --experimental-strip-types --test tests/timeline-export.test.mjs.

- beforeunload로 새로고침·탭 닫기·다른 문서로 이동을 경고한다. 이 경고 문구는 브라우저가 정한다. Navigation API 지원 브라우저에서는 취소 가능한 같은 문서의 SPA 이동/뒤로·앞으로 가기도 확인한다. 미지원 브라우저는 같은 출처 링크 클릭을 확인한다. 다운로드, 새 탭으로 열기, 해시 이동은 제외한다.

- 2026-11-22: 대상 버전 기본값 규칙을 변경했다. `has_content`는 해당 Phase/Version의 모든 제품·Build 중 항목 또는 마일스톤이 하나라도 있으면 true다. 월·정렬 설정만 저장된 표는 빈 내용으로 본다. 빈 0.0 재사용 시 현재 제품의 해당 Build만 갱신하고 revision을 증가시키며 다른 제품의 빈 표는 유지한다. 저장 트랜잭션 안에서 내용을 다시 검사해, 선택 이후 추가된 항목이 있으면 덮어쓰지 않고 거절한다. 백엔드 20개, 프런트엔드 버전 테스트 5개 및 TypeScript 검사 통과.

### 항목 다중 선택 이동 (2026-11-22)
- 편집 탭에서 Expand한 동일 Build 표 안의 항목을 클릭한 뒤 Shift+클릭으로 선택을 추가/해제한다. 선택된 항목 중 하나를 드래그하면 선택 항목 전체가 같은 일수만큼 이동한다. 마일스톤도 함께 선택할 수 있다. 선택되지 않은 항목을 일반 클릭하면 단일 선택으로 전환한다.
- 항목별 기간과 항목 간 날짜 간격을 유지하도록 표시 날짜 경계에서 그룹 전체의 이동량을 제한한다. 좌/우 방향키는 선택 그룹을 하루씩 이동하고, 드래그 중 Escape 또는 포인터 취소는 그룹 전체를 이동 시작 시점으로 복원한다. 양 끝 핸들은 해당 항목만 기간을 조절한다. 변경은 Save Changes로 저장하며 Cancel은 저장 전 상태로 되돌린다.

### 편집 가능한 PPTX 내보내기 (2026-11-22)
- 2026-11-22: 마일스톤 이름 색상을 검정 RGB(0, 0, 0)으로 변경했다. 기존 12px 폰트 크기는 유지하며 화면의 계산된 스타일을 사용하는 PNG/PPTX에도 동일하게 적용한다.
- 사용자가 PowerPoint에서 원, 선, 텍스트의 위치·색상·내용을 조절할 수 있도록 이미지 삽입을 개별 도형으로 교체했다. 전체 그룹과 Build 그룹은 그룹 해제하거나 그룹 내부 개체를 선택해 편집한다. PNG 미리보기와 PPTX는 같은 시점의 선택 Build 및 화면 좌표를 사용하며 PowerPoint 글꼴 렌더링에 따른 미세한 차이는 있을 수 있다.
- JSZip을 직접 의존성으로 등록하고, Node 기반 TypeScript 테스트에서 지연 로딩 모듈을 해석할 수 있도록 noEmit 환경의 allowImportingTsExtensions를 활성화했다.
- 검증: PPTX 중첩 그룹·고유 개체 ID·편집 가능한 원/텍스트·이미지 미포함, 기존 PNG 다운로드 테스트 3개, TypeScript 검사와 프로덕션 빌드 통과. PowerPoint 앱에서의 수동 편집 검증은 수행하지 않았다.

### 제품 전체 타임라인 (2026-11-27)

- 조회 탭 맨 위에 현재 제품·Phase·Version의 전체 타임라인을 표시한다. 활성 Build의 저장된 일정 구간이 겹치거나 빈 날 없이 이어지면 합치고, 어느 Build에도 일정이 없는 날은 공백으로 남긴다. 마일스톤은 원래 날짜와 Build를 유지한다.
- 전체와 개별 Build는 저장된 월 범위를 공통 날짜 축으로 사용한다. Build에서 제외한 월에 새 일정이 생기지 않으며, 저장된 월이 없으면 기본 월 범위를 사용한다.
- 제품명 옆 체크박스는 개별 Build와 독립적인 다운로드 선택이다. 기존 모든 Build 선택과 PNG/편집 가능한 PPTX를 유지한다. 일부 Build 조회 실패 시 불완전한 전체 일정을 내보내지 않는다. DB·API 변경은 없다.

### 타임라인 표시 크기 (2026-11-27)

- 조회 탭의 접이식 표시 크기에서 마일스톤 원 지름, 날짜, Phase, 항목 이름을 독립적으로 조절한다. 초기값은 각각 16, 12, 16, 12px이며 기본값으로 한 번에 복원할 수 있다.
- 현재 제품의 합산 행과 각 Build에 같은 설정을 적용한다. Phase는 제목의 Phase 값만 바뀌고 Version은 바뀌지 않는다. 마일스톤의 날짜 좌표와 일정 축은 크기 변경으로 바뀌지 않는다. 날짜와 항목 글자가 커지면 겹침을 줄이기 위해 줄 배치를 다시 계산한다.
- 설정은 현재 열린 로드맵 화면에서 제품/탭을 오가도 유지하되 새로고침 시 초기화된다. PNG와 편집 가능한 PPTX는 내보내기 시 같은 설정을 사용한다. 편집·비교 탭 및 데이터 저장에는 영향이 없다.

### 여러 제품 모아보기 (2026-11-27)

- 조회·편집·비교 뒤 네 번째 탭에서 공통 Phase·Version을 선택해 제품별 활성 Build의 합산 일정을 한 줄씩 보여준다. 모든 제품은 같은 날짜 축을 사용한다. 일정이 없는 날은 채우지 않으며 마일스톤은 유지한다. 그 조합에 저장된 일정이 없으면 빈 상태를 표시하고 다른 버전으로 대체하지 않는다.
- 제품 체크박스로 선택한 행만 한 PNG 또는 편집 가능한 PPTX로 함께 내보낸다. 조회 탭과 원·날짜·Phase·항목 글자 설정을 공유한다. 선택된 제품 전용 공유 링크는 제품 모아보기에서 숨긴다.
- 기존 제품별 Build 목록과 로드맵 조회 API를 읽고 동시 요청은 최대 6개로 제한한다. 조회 실패 행은 불완전한 합산을 그리거나 내보내지 않는다. 저장·권한·API·DB 변경 없음.

### Product Forecast / Chat 사이드바 (2026-11-27)

- 앱 사이드바에 Product Forecast와 Chat을 표시한다. 기존 로드맵 주소, 쿼리 기반 공유 링크와 API는 유지하고 Chat은 `/product-forecast/chat`에 둔다. 좁은 화면에서는 두 메뉴를 상단에 표시한다.
- Chat은 ProseMirror 기반의 평문 입력 테스트다. 붙여넣기, 실행 취소, Enter 전송과 Alt+Enter 줄바꿈, 한글 IME 조합 확인 Enter의 오전송 방지를 지원한다. 전송 문자열은 화면에만 표시되고 새로고침이나 이동 시 사라진다. LLM·외부 API·DB·메시지 자동 응답은 없다.

- Chat의 **+**는 파일 선택을 열고, 편집기에서 Ctrl+V로 이미지 파일을 붙여넣는다. 이미지 미리보기 제거, 이미지 단독 및 텍스트와 함께 전송을 지원한다. PNG/JPEG/WebP/GIF/BMP/AVIF만, 최대 4장과 이미지당 8 MB를 허용한다. 브라우저 object URL은 제거하거나 화면을 닫을 때 해제한다. 파일 업로드·서버 저장·드래그앤드롭은 이번 범위가 아니다.

- 기본 동선은 로드맵 **편집 → 채팅으로 편집**이다. 현재 제품·Phase·Version을 표시하는 패널을 화면 오른쪽 하단에 고정한다. 입력창 위의 대화 기록만 스크롤하며 전송 시 최신 메시지를 표시한다. 같은 편집 화면 안에서 닫았다 열면 대화와 작성 중인 메시지를 유지한다. 탭·제품·Phase·Version 이동 또는 새로고침은 저장하지 않는다.
- 기존 독립 Chat은 기본 비활성화한다. `NEXT_PUBLIC_ENABLE_STANDALONE_CHAT=true`로 개발 서버 재시작/프로덕션 재빌드 시 메뉴와 경로가 다시 열린다. 이는 기능 표시용 플래그이며 인증 권한은 아니다. 로드맵 저장 및 다음 Phase 등록에는 영향이 없다.
